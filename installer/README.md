# EXTB web installer

This independent Worker is intended for `https://extb.achiron.fyi`. It deploys checksum-pinned, published EXTB release artifacts directly to an authenticated user's Cloudflare account. Owner passwords are entered only on the forum.

## Operator configuration

Register and domain-verify a **public Cloudflare OAuth client**, using redirect URI `https://extb.achiron.fyi/oauth/callback`, authorization-code flow and PKCE. Configure required account permissions for Workers scripts/assets/subdomain deployment, D1 creation/migration queries and the Durable Object bindings. Request only permissions required by those endpoints; optional GitHub Builds permissions belong in a separately requested authorization scope. Set `OAUTH_CLIENT_ID`, the client-approved `OAUTH_SCOPE`, `RELEASE_MANIFEST_URL` and the independently verified lowercase hex `RELEASE_MANIFEST_SHA256` in Wrangler vars. Release URLs must be `https://github.com/royachiron/extb/releases/download/vX.Y.Z/...`.

Store `ENCRYPTION_KEY` as a Wrangler secret, using a base64-encoded 32-byte cryptographically random value. Do not put tokens or the encryption key in repository files. Provisioning sessions expire after one hour or sooner if OAuth expires. The cookie keeps only the random installation locator for a year; authentication is always checked against the server-side one-hour expiry, and later reconnection requires fresh Cloudflare authorization matching the original identity and account. Session credentials are encrypted with AES-GCM, and are revoked and removed after deployment. Resource IDs are retained without tokens so later operations can request fresh authorization.

Optional GitHub requires `GITHUB_CLIENT_ID`, secret `GITHUB_CLIENT_SECRET`, and callback `https://extb.achiron.fyi/github/callback`. Set `GITHUB_CF_SCOPE` to the approved optional Builds authorization scope. Users reauthorize Cloudflare, authorize GitHub, create their private repository, grant the Cloudflare GitHub App access once in Worker Settings → Builds and select an existing account deployment token. Its identifier is verified against the selected account. Secrets never enter the repository. The optional repository comes from the current EXTB template; its first build upgrades source and applies migrations before deploying the existing Worker and D1 database.

Run `npm run verify` in EXTB before publication. Run `npm run typecheck --prefix installer` to check only this package. `npm run deploy --prefix installer` deploys the installer after operator configuration and DNS access are available. Unconfigured OAuth returns HTTP 503; no success or live deployment is claimed without registration and separate-account end-to-end verification.

## Routes and deployment recovery

`/oauth/start` and `/oauth/callback` implement Cloudflare PKCE/state and verified userinfo identity. `/api/preview` returns a shared validated draft and escaped preview. `/api/install` accepts `{account,draft}` only after preview approval; browser mutations require an authenticated cookie, matching Origin and `x-csrf-token` from `/api/session`. Draft edits must be previewed again before approval.

`/api/status` exposes persisted stages and sanitized errors; `/api/retry` resumes the current stage. Migrations are recorded with their SQL in the same D1 batch. Database names are reserved before creation so lost responses recover the same resource; preexisting names fail. Worker retries inspect the migration tag so Durable Object migrations are not reapplied. `/api/handoff` delivers ownership only to the authenticated session as `/setup#ownership=...`; `/api/status` never exposes ownership credentials. The forum exchanges the fragment for its own setup cookie and removes it immediately. If owner setup expires, fresh Cloudflare authorization matching the original identity/account can issue a new credential. A guarded D1 transaction replaces only ownership settings and invalidates stale setup cookies; approved drafts, branding and content remain intact. An already completed forum returns its ordinary URL without rewriting anything.

`/api/github/start`, `/github/callback`, `/api/github/connect`, `/api/github/build` and `/api/github/status` support optional post-installation connection. Connection status does not claim a successful build: users can read the actual Builds status after fresh Cloudflare authorization. `/healthz` reports installer readiness without community content.
